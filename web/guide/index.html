Origin

Two strata, one system

The board and the game's own art pull in two directions. The board is flat, printed and calm. The game's sprites are airbrushed renders, and the story needs a place for strange, broken machine memory. The guide keeps both by giving each a job.

Outer stratum

Pelican modernism

Everything the player uses: the dialogue box, choices, dice, the puzzle editor, menus and docs. Flat geometric shapes, one clean sans, a short palette on warm paper.

Inner stratum

Mainframe comic ink

Only for found documents inside the story: Clipi's corrupted memory, old Company bulletins, salvage-yard signs. Halftone, heavy line, comic lettering.

Palette

Seven colours, each with a job

Paper and ink carry the page. Each accent belongs to a character or a kind of machine, so colour tells the player who is speaking before they read the name. Every pair below that carries body text passes WCAG AA at 4.5:1 or better.

Hard rule

Magenta is a flat fill, never a glow

Use magenta only as solid text, a solid badge, or a solid rule. Never as a shadow, an outer glow, a gradient or an edge. Set the background and the text colour together on every chip, so a badge never loses its fill and becomes unreadable.

The rule exists because of a real bug, shown under Sprites.

Type

Three faces, all free

Display · headings

Space Grotesk

Geometric and a little mechanical. It reads as a 1968 terminal without turning into chrome science fiction.

Body · everything you read

IBM Plex Sans

Humanist and legible at small sizes. The IBM name is a quiet joke in a mainframe story.

Mono · anything a machine emitted

(hesh roster)

IBM Plex Mono, for Rill code, terminal output and corrupted logs. A human character never speaks in mono.

Scale: a 1.25 ratio from a 16 px base (10, 13, 16, 20, 25, 31, 39 px). Spacing: a 4 px grid. Corners: 2 px.

Shape

Six rules for composition

  • Flat shapes, hard edges.No drop shadows, bevels or soft gradients. A shape is one flat colour plate.
  • One graphic idea per screen.Pick the one shape that carries the moment: a background, a character, or a panel.
  • Thick, even outlines.Redrawn or vector art uses one heavy line weight, like the atom-eye poster.
  • A grid may show.The puzzle panel sits on a faint grid. It is decoration, and it never lowers legibility.
  • No rainbow systems.Colour marks who or what, never a level or a rank.
  • Accretion, not replacement.A solved puzzle stays visible, folded into the next panel.

Sprites

The bug behind the magenta rule

The character art was cut out of a magenta background. Every cut-out kept a magenta rim or glow along its edge, and on a dark scene it showed as a pink halo. A tool in the repository, despill.py, finds magenta that touches the transparent outside of a sprite and removes it. Magenta that the art itself encloses, such as Clipi's screen band, stays.

The next step for the art is a duotone pass: shadows mapped to ink, highlights to the character's accent (Slim orange, the Terminal teal, Clipi magenta, Cargo Bot ochre), set in front of one flat deep-paper plate. That makes the airbrushed renders sit inside the flat system. It is not done yet.

Inner stratum

Clipi's memory, and Clipi's room

Two scenes leave the ordinary game view for a second visual mode, set with a mode inner line at the top of the scene (see docs/scene-format.md). Everywhere else, the game is the default stratum shown above. In these two, three rules change at once: a dot-halftone overlay and low scanlines over the stage, a heavier ink rule on the dialogue box, and choices drawn as flat tiles instead of a plain list.

Found document

  • Clipi reads a corrupted memory log back verbatim, in file order, line by line: no narration, no reaction from Clipi beyond the words themselves.
  • Clipi speaks as itself here, not as a sprite reacting to the log; the log is quoted, not staged.
  • The heavier top rule on the dialogue box shows plainly. The halftone and scanlines sit over the stage's photographic art and read faint there, the way they did over any busy image in Wave A.

Writing

Plain for instructions, precise for story

Two sources, for two jobs. Anything a reader must act on correctly the first time follows Simplified Technical English and Orwell. Dialogue and scene text take Gene Wolfe and Jack Vance as touchstones: their precision, not their difficulty.

Simplified Technical English

  1. One instruction per sentence.
  2. Active voice.
  3. Present tense for how things work; imperative for what to do.
  4. Instructions under 20 words; description under 25.
  5. Use the same word for the same thing, every time.
  6. Write the steps in the order the reader does them.

Orwell's six rules

  1. Never use a figure of speech you have seen in print.
  2. Never use a long word where a short one will do.
  3. If a word can be cut, cut it.
  4. Never use the passive where you can use the active.
  5. Never use jargon if an everyday word will do.
  6. Break any of these rules sooner than write something barbarous.

Wolfe and Vance, for story only

  1. One exact detail, not three adjectives.
  2. Never explain the world to the reader.
  3. One unusual word where it counts, not five.
  4. This licence stops at the fourth wall: a button label or an error message is always plain.

Project instructions

Paste this into an AI project

This is the whole guide as instructions for an AI assistant, such as a Claude project or a custom GPT. Paste it as the project's instructions, and the assistant will write and design within the system. The repository uses the same rules in AGENTS.md.

Project instructions
You help make LinkLoader, a sci-fi western visual novel with code puzzles. Follow these rules in everything you write or design.

LOOK
- Two strata. The interface (menus, dialogue box, choices, dice, puzzle panel, docs) is Pelican-book modernism: flat geometric shapes, one clean sans, a short palette on warm paper. Mainframe-comic ink (halftone, heavy line, comic lettering) is only for documents found inside the story, such as Clipi's corrupted memory.
- Palette: paper #F3EDDC, deep paper #EAE0C4, ink #1A1A1A, teal #1B4D5C (the Terminal, the Company), orange #B84A25 (Slim), magenta #951655 (Clipi, glitches, danger), ochre #8A6415 (Cargo Bot). Use white #FFFFFF only for text on teal, orange or magenta.
- Set the background and the text colour together on every chip or badge.
- Magenta is a flat fill: solid text, a solid badge or a solid rule. Never a glow, shadow, gradient or edge.
- Type: Space Grotesk for headings, IBM Plex Sans for body text, IBM Plex Mono for code and anything a machine emitted. A human character never speaks in mono.
- Flat shapes and hard edges, 2 px corners. No drop shadows, bevels or soft gradients.
- One graphic idea per screen. A faint grid may show as decoration.
- Colour marks who or what. Never use rainbow gradients or colour by level.
- Body text must reach 4.5:1 contrast.

WORDS
- For instructions, docs, UI labels, puzzle prompts and error messages, use Simplified Technical English and Orwell's six rules:
  - One instruction per sentence. Active voice.
  - Present tense for how things work; imperative for what to do.
  - Instructions under 20 words; description under 25.
  - Use the same word for the same thing every time.
  - Cut every word you can. No stock phrases.
- For dialogue and scene text, take Gene Wolfe and Jack Vance as touchstones:
  - One exact detail, not three adjectives.
  - Never explain the world to the reader.
  - One unusual word where it counts, not five.
- Never let story style into a button label, prompt or error message.

WHEN UNSURE
- Choose the plainer option.
- Name the rule you followed if someone asks why.
